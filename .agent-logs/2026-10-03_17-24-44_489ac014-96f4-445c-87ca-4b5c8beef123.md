## Data model (Supabase Postgres, row-level security by `owner_id`)

```
meetings            id, owner_id→auth.users, title, started_at, duration_ms,
                    source(seed|upload|browser), media_key(R2), media_kind(video|audio),
                    status(processing|ready|failed), error, calendar_event_id?, created_at
participants        id, meeting_id, name, email?, color         -- the speakers
transcript_segments id, meeting_id, participant_id, idx, start_ms, end_ms, text,
                    tsv(generated) · GIN(tsv), (meeting_id,start_ms)
chapters            id, meeting_id, idx, start_ms, end_ms, title, gist
summaries           id, meeting_id, template, sections jsonb  -- [{heading, bullets:[{text, at_ms}]}]
                    model, created_at · unique(meeting_id, template) · tsv(generated)
action_items        id, meeting_id, text, assignee_participant_id?, at_ms, done
highlights          id, meeting_id, created_by, start_ms, end_ms, note,
                    share_token? unique (null = not shared / revoked), view_count
calendar_accounts   user_id, google_email, refresh_token  -- server-only, no client policy
```

- **Templates:** a code constant (the prompts), not a table. They're generated on demand and cached in `summaries`.

- **Search** is one RPC, `search(q)`. It runs `websearch_to_tsquery` across titles, transcript segments and summaries. Each hit returns a highlighted snippet and `at_ms`, so a search result opens the meeting at the moment it was said.
